# Atoms Demo - AI 游戏生成器

## 项目简介
这是一个基于自然语言生成可运行 HTML5 游戏的 Web 应用。用户输入游戏描述（如“做一个简单的贪吃蛇游戏”），AI 会实时生成完整可玩的游戏代码，并直接在页面中渲染。

## 技术栈
- **前端界面**：Streamlit（纯 Python，快速搭建交互式 Web 应用）
- **大模型 API**：硅基流动（DeepSeek-V3）
- **数据持久化**：SQLite（保存每次生成的指令和生成时间）
- **部署平台**：Streamlit Community Cloud

## 实现思路
1. 用 Streamlit 搭建输入框、生成按钮和游戏渲染区域。
2. 用户点击“生成游戏”后，调用硅基流动的 DeepSeek-V3 模型，通过精心设计的 System Prompt 强约束模型只输出纯 HTML 代码（包含内联 CSS 和 JS）。
3. 收到代码后，用 Streamlit 的 `components.v1.html` 直接渲染，实现“输入 → 生成 → 可玩”的闭环。
4. 同时将用户输入和时间戳存入 SQLite，在左侧侧边栏展示历史记录，实现数据持久化。

## 测试视角与发现的问题
作为测试工程师，我在开发过程中重点关注了 AI 生成式产品的边界情况：
- **发现的问题**：在生成贪吃蛇游戏时，曾遇到“重新开始后必须立即按方向键才能激活”的异常。这暴露了 AI 生成代码在状态初始化和事件绑定上的不确定性。
- **应对策略**：通过调整 System Prompt，强制要求模型“重新开始时先重置所有游戏状态，再启动游戏循环”，显著提升了生成代码的健壮性。
- **测试思考**：对于 AI 生成类产品，测试重点不应仅限于“能否跑通”，更应关注**模糊指令的容错性**、**生成代码的边界处理**，以及**高并发下的响应稳定性**。
